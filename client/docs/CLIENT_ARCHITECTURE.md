# Windows 仪器客户端总体方案

## 1. 技术选择

建议使用 **.NET 10 LTS + WPF**。它适合长期运行在 Windows 仪器电脑上，置顶窗口、全局快捷键、剪贴板、SQL Server、系统托盘和自包含发布都比较成熟。两个客户端放在同一个解决方案中，共享核心库，但生成两个独立安装包：

```text
ToyLims.Client.Core       HTTP、认证、本地队列、日志、通用置顶窗口
ToyLims.Client.Xrf        OXSAS 工作列表与结果适配器
ToyLims.Client.Standard   通用快速录入表格
```

XRF 最小客户端已经建立独立 `.csproj`；公共核心库和标准客户端等第二种客户端启动后再拆分，避免第一版过度设计。

## 2. 总体边界

```text
LIMS 服务端（唯一业务真相）
        ↑↓ HTTPS/JSON，任务领取与幂等结果提交
Windows 客户端（本地缓存、显示、仪器适配）
        ↑↓
OXSAS SQL Server / 操作者粘贴录入
```

- 客户端不直接访问服务器的 SQLite 数据库。
- 服务端负责样品状态、任务归属、单位、报告计算、权限和审计。
- 客户端只负责领取任务、关联本机仪器数据、校验预览和上传原始结果。
- 每次上传都带稳定的 `task_id`、`client_id` 和 `idempotency_key`；重复发送返回原结果，不生成重复读数。

## 3. 两种客户端共用能力

### 3.1 置顶窗口

- 主窗口设置 `Topmost=true`，默认吸附屏幕上边缘。
- 展开时显示任务表；收起后保留约 40 px 状态条，避免长期遮挡仪器软件。
- 可锁定位置、记住显示器和坐标，支持多显示器及 DPI 缩放。
- 弹出错误时不抢走仪器软件正在输入的焦点；用户点击客户端后才进入编辑。
- 托盘图标显示在线、断线、待上传和错误状态。

### 3.2 本地可靠性

- 本地 SQLite 只保存任务缓存、草稿、待上传队列和同步游标，不保存服务器业务主表。
- 访问令牌使用 Windows DPAPI 加密；日志不得记录密码、令牌或完整数据库连接串。
- 上传采用 outbox 队列：先本地落盘，再发送，服务端确认后标记完成。
- 网络失败指数退避；恢复联网后先校时、刷新任务状态，再继续上传。
- 客户端心跳包含版本、机器名、绑定仪器和最后同步时间，服务端可以显示客户端是否在线。

## 4. 服务端 API 草案

建议新增独立的 `/api/v1/instrument-client/` 命名空间，不复用网页表单接口：

| 接口 | 用途 |
|---|---|
| `POST /session` | 使用设备凭据换取短期令牌 |
| `POST /heartbeat` | 上报在线状态、版本和同步游标 |
| `GET /jobs?instrument_id=...` | 增量下载待测任务 |
| `POST /jobs/{id}/claim` | 领取任务，防止两台客户端同时处理 |
| `POST /jobs/{id}/release` | 释放误领或无法测量的任务 |
| `POST /results/batch` | 批量、幂等上传原始读数 |
| `GET /xrf/workday` | 获取当日批次及 101–208 位置分配 |
| `POST /xrf/observations` | 上报 OXSAS 分析记录和关联状态 |

下载任务至少包含：LIMS 编号、显示名称、溶样名称、元素、服务器仪器 ID、方法代码、单位、样品状态和版本号。服务端应返回任务版本；来样页修改过任务后，旧版本上传必须被拒绝并提示刷新。

设备认证建议由管理员在设置页生成一次性配对码，而不是让客户端保存普通用户密码。正式跨机器使用时启用 HTTPS；即使在实验室内网，也不应裸传设备令牌。

## 5. XRF 客户端

### 5.1 下载与排位

- 业务日定义为当天 08:00 至次日 07:59:59。
- 服务端是位置分配的唯一来源，按 101–208 分配；客户端不得自行猜测下一个位置。
- 客户端启动或到达 08:00 时调用 `GET /xrf/workday`，创建或核对当天批次，并把“位置—LIMS 编号—方法”显示给操作者。
- 方法使用服务端方法代码映射到 OXSAS `Prog_Hdr.Name`，例如配置 `WUNI0820 ↔ 0820WUNI`，不在程序中写死方法名或数据库 ID。
- 同步前先做差异预览：新增、已存在、冲突、位置被占用。只有完全可解释的新增项才自动下发。

### 5.2 OXSAS 写入策略

实施顺序必须是：厂家支持的导入/API优先，其次是经过验证的数据库适配器。当前资料明确提示 OXSAS 运行时持续写库，因此第一版只读，不直接修改 `oxsas_db`。

若最终必须写数据库：

1. 适配器仅允许调用一个经过版本检查的事务过程，不允许散落 SQL。
2. 写前验证 OXSAS 版本、目标库结构、批次不存在冲突，并做数据库备份。
3. 写入 `Batch_Batches → Batch_Collections → Batch_BatchColls → Batch_CollSamples` 时在一个事务中完成。
4. 写后重新读取核对；任何异常整笔回滚并停止自动下载。
5. 客户端配置只存方法名称映射，绝不硬编码 `Prog_Hdr.ID`。

### 5.3 结果上传

- 定量结果从 `ANALYSES` 的 `Analyses + Attributes + Elements` 只读获取。
- 使用 OXSAS 分析 ID 和来源标识保证上传幂等；LIMS 编号、方法、分析时间和原始样品名仅作为人工核对信息，不由客户端决定关联。
- 最新分析必须等属性和元素行稳定后再读取，连续两次快照一致才视为完成。
- 相同分析可能存在复制记录，上传前按分析指纹去重。
- 定量结果自动上传；UniQuant 只自动上传人工处理完成且 `IsAddedToHundred=1` 的最终组成。
- UniQuant 通过 `Line → Atom` 同时读取 `Atom.Name` 元素名和 `Atom.OxideName` 氧化物名；有氧化物名时一定有元素名。`JobChan.Conc` 只有一个当前口径数值，由 `GeneralData.Chemistry` 决定表示方式。后续载荷应保留名称对和 Chemistry，不上传 CPS、背景和谱线原始载荷。
- 服务端保存 OXSAS 原始分析 ID、样品名、方法、时间、关键选项和最终组成；新扫描始终进入未关联池，由网页数据页或仪器页手工选择 LIMS 样品。

## 6. 标准仪器客户端

- 安装时绑定服务器中的一台仪器，主界面只显示该仪器待测任务。
- 行结构建议为：位置/编号、溶样、元素、单位、读数 1…n、是否参与、状态。
- 支持从仪器软件或 Excel 直接粘贴一列/多列，Enter、Tab、方向键连续录入。
- 单位由服务端任务决定，例如 ICP-OES 为 ppm、ICP-MS 为 ppb，客户端不能自行切换。
- 本地实时检查空值、非数字、重复任务和异常数量级，但不复制服务端最终换算公式。
- “提交本页”前给出新增、覆盖、跳过的汇总；已提交数据再次修改需要明确原因。

## 7. 推荐实施顺序

1. **服务端契约**：先建立客户端、设备令牌、任务增量同步、任务领取、幂等结果上传和心跳表/API。
2. **标准客户端**：用它验证 WPF 置顶界面、配对、任务下载、键盘录入、断线草稿和批量上传。
3. **XRF 只读上传**：连接测试库，先实现 OXSAS 结果发现、去重和预览，再开放定量自动上传；样品关联在服务端网页手工完成。
4. **XRF 工作列表下载**：先生成差异预览或导入文件；确认厂家接口后，再决定是否启用受控数据库写入。
5. **试运行**：测试服务器和测试 OXSAS 库并行运行至少一个完整业务周期，核对样品、位置、方法、单位和重复上传。

这个顺序能先把公共通信和数据可靠性做稳，同时把风险最高的 OXSAS 写库留到最后单独验证。

## 8. 开始编码前要确认的事项

- 仪器电脑可用的 Windows 与 .NET 版本、是否允许安装 .NET Desktop Runtime。
- 服务端的内网地址、HTTPS 证书和断网最长持续时间。
- OXSAS 是否提供官方工作列表导入/API，以及允许写入的维护窗口。
- 当日超过 108 个 XRF 位置时是拒绝、开第二批次还是人工处理。
- 手工关联 XRF 扫描后由服务端更新样品任务进度。
- UniQuant 只保存最终浓度和关键计算选项，不保存 cps 或标准误。
