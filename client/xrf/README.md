# XRF 客户端

目标：运行在 OXSAS 仪器电脑上。连接 LIMS 成功后显示独立的置顶待测样品窗口；
SQL 设置和自动同步状态位于另一个不置顶窗口。

## 当前第一版

- .NET 10 WPF，两个真正独立的窗口。
- LIMS 地址默认 `http://127.0.0.1:5000` 且可修改；客户端启动后自动连接，不要求操作员输入设备令牌或登录凭据。
- 置顶窗口以卡片显示待测样品、方法和检测项目，不显示进样名；单击样品名称即可复制。
- 从本机 `http://127.0.0.1:5000` 下载未完成的 XRF 样品。
- 待测窗口不设置额外复制按钮，样品名称本身就是复制入口。
- 使用只读 SQL 查询 `ANALYSES`。启动时核对并补传历史定量分析，之后持续同步最近结果。
- 同时只读提取分析属性中的批次 `$BA$`、方法 `$ME$` 和样品名，并随结果上传。
- 普通定量查询排除 `X_UQ`；所有有定量结果的扫描都会自动上传，未登记 LIMS 的样品也会保留并持续尝试关联。
- UQ 只读取 Film 为 `PP 4mu`（兼容 `4um`/`4µm`）且已生成最终组成的人工处理记录。
- UQ 仅上传 `IsAddedToHundred=1` 的 `Conc` 最终值；名称通过 `Line → Atom` 映射为元素或氧化物，不上传 CPS、背景、标准误或其他谱线字段。
- 服务端会在启动迁移时自动清理历史 `Bg*` 背景项，并把历史 XRF 数值统一为 5 位有效数字。
- 服务端按 OXSAS Analysis ID 或 UniQuant General/Job ID 幂等保存；客户端每 5 秒同步最近结果，启动时按精确 ID 核对完整历史。
- 每 5 秒联合查询 `oxsas_db.Batch_*` 和 `Gen_InstrState`，向 LIMS 上报终端机器名、版本、测量状态以及当前样品、方法、批次、位置、开始时间和 `BatchID:CollectionID:RowID` 运行实例编号；不再把历史结果列表的选中行当作当前样品，也不以可能重复的样品名作为运行键。
- 暂不创建或修改 Batch，也不写入任何 OXSAS 数据库；批次字段仅作只读追溯。

开发运行：

```powershell
dotnet run --project client/xrf/ToyLims.XrfClient.csproj
```

已发布的 x64 轻量单文件位于：

```text
client/xrf/publish/win-x64-single/ToyLims.XrfClient.exe
```

每次修改 XRF 客户端后都必须重新发布此单文件 EXE；发布保持 `SelfContained=false`，依赖目标电脑外置的 .NET 10 Desktop Runtime。

该版本不捆绑 .NET，目标电脑需要预先安装对应的 .NET 10 Desktop Runtime；优点是文件约 7.5 MB，升级客户端时不重复携带运行时。首次测试顺序：

1. 在项目根目录运行 `python server.py`。
2. 浏览器中创建或确认一个勾选 XRF 的待测样品。
3. 打开客户端，连接 LIMS；连接成功后置顶待测窗口才会出现。
4. 在置顶窗口复制进样名称或样品名称。
5. 在 OXSAS 中手工进样并使用复制的名称；名称可能重复时优先使用 LIMS 编号。
6. 分析结束后无需人工上传；普通定量和人工处理完成的 UQ 都会自动同步。
7. 如需立即核对全部历史，可在主窗口点击“立即补传并同步”。

OXSAS SQL 账号由客户端固定配置，不在界面显示；测试阶段 LIMS 与客户端运行在同一电脑，因此本机接口无需设备令牌。

## 后续计划

- 从 LIMS 下载 XRF 待测任务、方法和自动进样器位置。
- 以每天 08:00 为业务日边界，创建或核对当日批次，位置循环使用 101–208。
- 将任务写入 OXSAS 工作列表；优先使用厂家支持的接口，数据库写入作为最后阶段的受控适配器。
- 只读监控 `ANALYSES`，自动识别完成的定量结果并幂等上传。
- 断网时保存待上传结果，恢复后继续，不重复提交。
