# toy-lims 项目说明

一个面向**无机分析实验室**的轻量级 LIMS（实验室信息管理系统），用于记录来样、管理检测流程、录入分析原始数据、自动换算质量分数并生成报告单。

服务端使用 **Flask + PostgreSQL + Waitress**，SQLite 保留用于自动化测试和旧库迁移；浏览器端使用原生 HTML/CSS/JavaScript，仪器侧提供 **.NET 10 WPF** 客户端。项目面向局域网内的小型实验室，优先保证部署简单、数据可追溯和仪器操作便捷。

本系统由陈炫霖构思，由**Kimi K3**，**GLM 5.3 Flash**和**GPT 5.6 Sol**构建。
目前它还是叫**toy-lims**，但是它完善后将被叫做**Lil' Lims**
---

## 1. 功能概述

Web 系统分为九个页面：

| 页面 | 作用 |
|------|------|
| **来样** | 登记样品、设计溶样/稀释方案、自动生成平行样名称、打荧光粗扫 |
| **数据** | 顶部可搜索未关联 XRF 扫描并手工关联当前样品，显示全元素粗扫结果（参与报告项标浅蓝）；下方录入其他仪器原始值，所有输入自动保存 |
| **仪器** | 实时显示标准仪器和 XRF 客户端状态、当前用户/样品/方法/批次，追溯 XRF 与 UniQuant 扫描历史，并为未关联扫描手工选择 LIMS 样品 |
| **结果** | 汇总已制样之后所有样品的计算结果；常规结果使用元素卡片，XRF 使用紧凑最终组成网格，支持审核确认、参与最终值调整和特权手工补录 |
| **报告** | 勾选多个已审核样品批量编排报告，合并打印原始分析记录（A4 横向）和分析报告票（A5 纵向），支持整组排序 |
| **审计** | 集中查看最近 500 条操作记录，按关键词、动作和对象类型筛选 |
| **用户** | 维护用户能力组合、普通/管理实体终端及登录页顺序 |
| **设置** | 维护分析项目、仪器、定容容量、稀释方式、滴定方法、样品模板、报告版式和结果元素顺序模板 |
| **关于** | 快捷键速查说明 |

### 全局快捷键

| 快捷键 | 作用 |
|--------|------|
| `1` ~ `9` | 按顺序切换顶部页签 |
| `/` | 聚焦当前页搜索框 |
| `N` | 新建样品（仅来样页） |
| `E` | 导出当前页 Excel（来样=总览、数据=数据 Excel、结果=结果报告、报告=Excel 报告） |
| `[` / `]` | 列表上一页 / 下一页（来样、结果、报告） |
| `Esc` | 输入框失焦；结果页中再按一次收起最近展开的样品 |

单键快捷键在输入框打字时自动失效；错误或授权对话框打开时不响应。完整说明见“关于”页。

## 2. 运行方式

### 2.1 启动

```bash
cd "D:/文件/Projects/toy-lims"
python -m pip install -r server/requirements.txt
python server.py
```

服务默认运行在 **http://127.0.0.1:5000**。第一次打开会进入初始化页面，创建固定首个用户 `cxl`，并设置“二组”和“管理终端”的终端密码。已有用户的数据库升级后只需验证现有管理员密码并初始化终端，不会重建或删除用户。

`python server/app.py` 可用于本机开发；日常运行仍使用根目录的 `server.py`，它会转入 `server/run.py` 并通过 Waitress 提供服务。PostgreSQL 地址在 `server/app.py` 顶部的 `POSTGRES_CONFIG` 中集中配置，也可通过 `LIMS_DATABASE_URL` 整体覆盖。`LIMS_HOST`、`LIMS_PORT`、`LIMS_XRF_CLIENT_TOKEN` 和 `LIMS_STANDARD_CLIENT_TOKEN` 分别调整监听地址和仪器设备认证。

### 2.2 环境依赖

- Python 3.10+
- Flask 3.x
- openpyxl 3.x（Excel 业务工作簿导出与上传）
- Waitress 3.x（正式 Web 服务）
- psycopg 3.x（PostgreSQL 驱动）

正式业务库位于 PostgreSQL，启动时会检查并补建当前 schema。旧 `server/lims.db` 作为迁移源和回退档案保留，不再由 Web 服务写入。SQLite 模式仍支持 `python server/backup_now.py`；PostgreSQL 正式库应由数据库服务器使用 `pg_dump`、计划任务或存储快照备份，应用不会把远程 PostgreSQL 伪装成 `.db` 文件。

请求日志是可选功能。在 `server/app.py` 顶部将 `REQUEST_LOG_ENABLED` 设为 `True` 后，服务会把时间、来源 IP、请求方法、路径、状态码、耗时、用户和终端写入 `server/logs/requests.log`；日志每天午夜轮转为带日期的文件并永久保留，不写入数据库或网页，也不记录密码、令牌和请求正文。`LIMS_LOG_DIR` 可调整日志目录。

### 2.3 终端、用户和能力

系统认证按终端类型提供三种入口：

- **普通终端**（初始为“二组”）登录后可浏览全部内容和打印，但不能直接修改。首次修改时页面右下角要求只输入用户密码，系统据此识别操作者并检查其是否勾选了对应能力；连续写操作可复用授权，最后一次成功修改后 2 分钟未再修改则自动失效。也可点击页头“结束授权”立即清除。
- **个人终端**是所有启用用户默认开放的系统入口，不需要创建或选择具体终端。用户直接使用用户名和用户密码登录，登录期间始终使用该真实用户的能力和审计身份，不需要为普通写操作重复授权。
- **管理终端**登录后以“管理员 · 管理终端”的终端身份执行修改，不要求输入用户密码。审计记录明确保存管理终端身份。
- 打印只使用页面当前内容，不会隐式保存或触发用户授权；需要持久化报告票面信息时应明确点击“保存票面信息”。

用户不再划分为收样员、分析员、审核员或管理员，而是直接勾选所需能力：样品登记与修改、检测数据录入、报告编辑、审核与发布、基础设置维护、用户管理和终端管理。一个用户可以组合这些能力，也可以不勾选任何能力作为纯浏览账号。创建或修改用户时只能授予当前操作者自己已有的能力，且不能修改权限高于自己的账号。旧数据库升级时会把原角色自动换算成等价能力组合，之后权限判断不再读取角色。

由于普通终端仅凭密码识别操作者，所有启用用户必须使用不同密码；新增用户和重置密码时服务器会强制检查。能力和两分钟授权均由服务器端检查，隐藏按钮不是唯一防线。

顶部独立的**用户**页维护用户以及普通、管理两类实体终端。用户支持修改登录名、姓名、能力组合、密码和启停；实体终端支持新增、改名、切换普通/管理类型、重置密码、启停，以及通过上移/下移调整登录页显示顺序。个人入口不在终端管理中显示，对所有启用用户自动开放。当前正在使用的实体终端不能停用或切换类型，系统始终至少保留一个具备“用户管理”能力的启用用户和一个启用的管理终端。所有用户和终端密码均要求非空，不限制最短长度。

Web 页面每 600 毫秒通过轻量状态接口检查数据修订号，只有发生变化时才刷新当前业务页；仪器页每 2 秒刷新在线状态。输入控件聚焦时暂停自动重绘，避免覆盖正在填写的数据。独立审计页显示最近 500 条记录，终端、用户、样品、设置和仪器客户端操作均可追溯。

样品创建后获得不可重复的正式编号，如 `20260826-001`。用户可见的生命周期为：未制样 → 已制样 / 未测量 → 测量中 → 已测量 / 未出报告 → 已出报告。审核确认发生在“已测量 / 未出报告”阶段内，审核前后显示名称相同；审核通过后才能发布报告。未审核的样品可按状态机退回或作废，已出报告和已作废均为终止状态。

## 3. 核心数据模型

```text
samples（样品）
    └── preparations（溶样方案：称样量 / 定容体积 / 稀释倍数）
            └── sample_analytes（该溶样下的具体分析项）
                    ├── readings（平行原始读数）
                    └── results（辅助数据 / 滴定变量）

samples
    └── sample_analytes（preparation_id 为空：原样直测，目前用于 XRF）

samples（workflow_type = special，其他样）
    └── special_results（专项原始数据和自动计算结果）
            └── special_methods（独立的专项仪器、字段、公式和记录表格式）
```

关键表说明：

- `analytes`：元素或指标（H–Bi 全周期表，去掉放射性 Tc/Pm；另含 pH、TOC、NPOC）。
- `chemical_elements`：1–83 号化学元素参考数据，保存原子序数、符号、中文名和原子量；Tc、Pm 使用常用质量数并有独立标记。该表暂不参与现有计算，供后续化学式、摩尔质量或滴定公式功能使用。
- `common_oxides`：68 种常见 XRF 报告氧化物，关联元素表并保存化学计量数、摩尔质量、元素质量分数和元素转氧化物系数，是 XRF 元素↔氧化物报告换算的唯一样式来源；多价元素可有多个候选氧化物，系统不自动猜测价态。
- `instruments`：仪器设备（XRF、ICP-OES、ICP-MS、AAS、TOC、滴定、pH 计、F 离子选择电极等）；ICP-OES 原始值按 ppm，ICP-MS 原始值按 ppb（μg/L）。设置页可调整默认仪器顺序，数据页和报告计算明细均按该顺序显示。
- `instr_analytes`：每台仪器能测哪些项目（在设置页维护）。
- `dilutions`：二次稀释方式；界面优先使用 `5/100`、`5/250` 这类“移取体积/再次定容体积”写法，数据库同时保存自动换算出的倍数。
- `volume_presets`：来样和模板可选择的首次定容容量；默认包含 `100 mL` 和 `250 mL`，新建溶样默认 `250 mL`。
- `methods`：滴定方法及其公式。
- `templates`：常用样品模板（固定类型一键填充来样表单）。
- `samples`：样品基本信息（名称、类型、是否液体、是否 XRF、**样品类型备注**），以及报告票的来样单位、报告编号、分析日期、分析人和审核人。
- `preparations`：一路溶样记录，包含独立名称、称样量、定容体积、稀释倍数。
- `sample_analytes`：真正的分析任务行。`preparation_id` 为空表示**原样直测**；有值表示走对应溶样方案。
- `readings`：同一任务下的**平行读数**（每遍独立原始值和是否参与计算的标记）。
- `results`：辅助数据（回标等）和任务级选择标记。
- `special_methods`：专项检测方法，与常规元素、仪器和滴定方法隔离，保存录入字段、单位及自动计算公式。
- `special_results`：其他样的专项原始数据、计算结果和完成状态；不会创建溶样或常规元素任务。
- `standard_client_sessions`、`standard_client_status`：标准仪器客户端的用户会话、在线状态和最近录入摘要。
- `xrf_analyses`、`xrf_values`：统一保存 OXSAS 普通定量和人工处理完成的 UniQuant 最终组成。新扫描一律先保存为未关联，不根据样品名、LIMS 编号或客户端样品 ID 自动匹配；操作者随后在数据页或仪器页手工选择 LIMS 样品。UniQuant 结果同时保留元素名与氧化物名（`alt_name` 为名称对的另一侧）。`xrf_report_targets` 按样品保存每个元素族的报告口径目标，未配置的样品按 `use_report` 勾选参与。`uq_analyses`、`uq_channels` 仅保留旧数据兼容。历史 XRF 结果会在启动迁移时自动清理 `Bg*` 背景项并统一为 5 位有效数字。
- `terminals`、`users`、`audit_logs`：终端入口、用户能力和操作审计。

## 4. 来样流程

### 4.1 填写样品信息

- **样品名称**：如 `AB2602`。
- **样品类型**：可选备注，如 `Zn(OH)2沉淀`、`ZnO焙砂`，会显示在样品卡和报告单上；已用过的类型会自动联想。
- **类型**：固体 / 液体 / 其他样；其他样使用专项检测方法，不建立常规溶样任务。
- **打荧光（XRF）**：勾选后单独输入 XRF 项目，它们不混入溶样后的仪器分配。

### 4.2 输入分析项目

在“溶样后待测元素”框直接输入即可，例如：

```text
Ag, Cu, Fe, pH
```

系统会按逗号、顿号、分号或空格切分，**大小写不敏感**地匹配已登记的分析项目，识别结果显示为绿色标签；识别不了的显示为红色 `?` 标签，不会进入样品。

### 4.3 设计溶样方案

一路溶样方案包含：

- 称样量（g） / 定容容量（mL）：容量从设置中的预设下拉选择，新建溶样默认 `250 mL`；液体样时自动隐藏。
- 二次稀释：下拉选择，按实际操作显示为 `移取体积/再次定容体积`，例如 `5/100`；系统内部自动按 `100 ÷ 5 = 20` 倍计算。
- 份数：1 表示只做一份；大于 1 表示做平行样。
- 测定项目：可留空（默认使用样品全部项目），也可只写本路要测的部分项目，例如 `Ag` 或 `Cu, Fe, pH`。
- 仪器分配：点击元素可连续多选，然后把任一已选元素拖到 ICP、AAS、滴定等仪器；每一路溶样可以使用不同的仪器组合。拖回“未分配”即可取消。滴定项目在对应仪器下直接选择滴定方法。

#### 自动生成与自定义名称

- 名称留空、份数 = 1：`{样品名}*{计算倍数}`，例如选择 `10/100` 后生成 `AB2602*10`。
- 名称留空、份数 > 1：`{样品名}-{序号}*{计算倍数}`，例如选择 `5/250` 后生成 `AB2602-1*50`、`AB2602-2*50`。
- 名称也可以直接修改。多份时可写 `消解液-{n}`，系统会把 `{n}` 替换为序号；不写 `{n}` 时自动在自定义名称后追加 `-1`、`-2`。

“溶样名称（可改）”列会实时预览。名称使用计算倍数，操作记录和打印票仍使用 `5/250` 这类实际移取/定容写法。不同路可以使用不同的二次稀释和测定项目。

### 4.4 样品模板

在**设置**页可以保存常用模板。来样页选择模板并点击“应用”后，会自动填充：

- 分析项目
- 样品类型（固/液）
- 是否打荧光
- XRF 方法和默认参与报告的 XRF 项目
- 任意多路溶样的称样量、定容容量、稀释方式、份数和分路项目
- 每个项目的默认仪器和滴定方法
- 模板自己的报告元素顺序

### 4.5 查询和修改已有样品

来样页采用样品卡片工作区，默认显示固体样，每张卡片直接列出全部待测元素/指标和溶样数量，也可切换查看液体样、其他样或全部样品。点击卡片会原地展开样品名称、类型、分析项目、XRF 选项和全部溶样方案并直接编辑；数据/报告页也可跳转编辑当前样品。点击“复制新建”可以完整继承已有样品配置并另存为新样品。保存修改时，未改变的分析任务及其原始结果会继续保留。

来样、数据和报告页共享同一个“当前样品”。样品卡可直接点击“录数据”，数据页可直达报告，报告页可返回数据；普通页签切换也会保留当前样品。页头始终显示当前样品，点击即可返回其样品资料。样品列表分页显示（每页 20/50/100/200 可选），当前页面会写入地址栏，浏览器刷新后自动回到原页面（含当前样品）。

页面任意位置右键可打开系统菜单：复制当前文字或表格选区、查看当前样品及状态，并快速切换到来样、数据、报告三个页面。在样品卡上右键时，该卡片会自动成为当前样品。

### 4.6 其他样与专项检测

不需要溶解、称样定容或常规元素分配的样品，来样时选择“**其他样**”。此时只填写样品名称、备注和专项检测方法，系统不会建立 `preparations` 或 `sample_analytes` 任务。

目前按 `image/` 中的实验室原始记录表内置五类专项方法：水分分析、煤/炭精分析、石膏分析、碳硫分析和量热分析。它们使用独立的数据表和审计字段，不与 ICP、AAS、XRF、pH、滴定等常规分析配置混用。

## 5. 数据录入

### 5.1 按仪器分组

数据页选择样品后，所有分析行按来样页已经分配好的**仪器**分组显示。未分配仪器的项目会提示返回来样页处理；每个任务行会显示所属溶样名称。

### 5.2 完成制样并开始测量

新样品最初为“未制样”。先点击“制样完成”进入“已制样 / 未测量”，再点击“开始测量”进入“测量中”，数据页随后解除只读。仪器和滴定方法在来样页按溶样分配；数据页只负责原始读数、是否参与计算和辅助数据。XRF 项目仍固定到 XRF。

- 每行可点“+再测一遍”追加**平行读数**；多遍读数仅用“参与”勾框决定是否纳入计算。勾选多遍自动求平均，只勾选一遍就直接采用该遍；只有一遍时无需显示勾框。

### 5.3 辅助数据（回标）

所有仪器都可填写回标数据：

- 在“辅助数据”列填入**标称值**和**回读值**，勾选“带标”，则该行最终结果自动乘以 `回读 ÷ 标称`。
- 例如 10 ppm 标准回读为 9 ppm，勾选后结果乘以 0.9。

### 5.4 自动保存

原始值、滴定变量、参与状态和回标等输入在失焦或变更后自动保存。只完成部分任务时样品仍显示“测量中”；全部检测任务均有结果后，样品自动进入“已测量 / 未出报告”。

### 5.5 表格批量操作

溶样方案表和原始数据表支持鼠标拖选和 `Shift` 扩选，选区可用 `Ctrl+C` 复制为制表符文本，也可从 Excel 直接用 `Ctrl+V` 粘贴。向溶样表粘贴多行时会自动追加缺少的行。选择多格后按 `Ctrl+D` 可把首格向下填充；拖动活动单元格右下角的填充柄时，单格会复制，两个及以上连续数字会按差值递增。

### 5.6 专项数据录入

其他样在数据页显示对应专项方法的简化录入表。操作者填写原始字段，灰色结果字段由方法公式自动计算；必填原始字段齐全后，该专项任务完成，样品进入“已测量 / 未出报告”。水分、灰分、分析水、挥发分、固定碳等项目自动换算，碳硫和量热结果直接录入。专项字段的审计记录使用中文业务名称，不显示数据库内部字段名。

### 5.7 标准仪器客户端

`client/standard/` 是面向 ICP-OES、ICP-MS、AAS、离子电极和 pH 等数值型仪器的 .NET 10 WPF 快速录入客户端。它按固定仪器下载待测任务，提供主窗口和置顶浮窗；用户使用具备“检测数据录入”能力的 LIMS 密码登录，10 分钟无录入活动后会话失效。提交按批次原子保存并带幂等编号，网络重试不会产生重复读数。

客户端配置固定保存在可执行文件同目录的 `standard-client.json`，操作人员不能从界面修改服务器地址、设备令牌或仪器绑定。发布程序位于 `client/standard/publish/win-x64-single/`，目标电脑需安装 .NET 10 Desktop Runtime。

### 5.8 XRF / OXSAS 客户端

OXSAS 普通定量和已人工处理完成的 UniQuant 结果上传后均进入未关联扫描池。系统不会按原始样品名自动认领，也会忽略上传载荷中的 `sample_id`；这样可避免现场命名重复、后缀变化或错贴编号造成误关联。每个 LIMS 样品最多关联一条 XRF 扫描：数据页可按原始样品名、方法、批次或扫描编号搜索，选中后搜索结果自动隐藏；如需更换扫描，应先使用“解绑当前扫描”。仪器页也可完成关联或解绑。操作需要“检测数据录入”能力，不能修改已审核或已作废样品，并写入审计记录。旧数据如存在重复关联，升级时只保留最新扫描，其余退回未关联池。

`client/xrf/` 运行在 OXSAS 仪器电脑上，以只读方式查询普通定量结果、UniQuant 数据和仪器实时状态，不修改 OXSAS 数据库。客户端每 5 秒同步状态和 UQ 分析，普通定量结果由操作者确认上传；服务端按外部分析 ID 幂等保存。发布程序位于 `client/xrf/publish/win-x64-single/`。

仪器客户端只通过 HTTP API 连接 LIMS，不直接访问 PostgreSQL 或旧 `server/lims.db`。跨机器访问时必须分别配置 `LIMS_STANDARD_CLIENT_TOKEN` 或 `LIMS_XRF_CLIENT_TOKEN`；用户密码和设备令牌承担不同职责。

### 5.9 结果页

结果页汇总“已制样”及之后所有阶段（测量中、待审核、已审核）的样品。要点：

- **多样品同时展开**：点击行展开该样品，已展开的样品不会收起；常规结果以**元素卡片**呈现（一行最多 5 张卡片），卡片头显示最终值，卡片内列出各溶样/仪器读数。XRF 普通定量和 UniQuant 只显示紧凑的最终组成网格，不展示 UniQuant 关键选项；每项结果按 5 位有效数字显示，并在元素或氧化物旁直接勾选是否参与最终结果。
- **勾选导出**：行首复选框或 `Ctrl+点击` 可勾选样品（不触发展开）；勾选跨页保留，“全部取消”一键清空，工具栏支持每页 50/100/200 条和翻页。
- **审核与参与**：展开后可审核确认、特权退回、调整各读数“参与最终值”；样品审核锁定后需退回才能修改。
- **手工补录**：具备特权能力并再次验证密码后可补录或恢复系统计算。补录结果以卡片展示，直接显示补录值和系统原值，操作者与时间在横幅中说明，全部写入审计。
- **收起**：`Esc` 从最近展开的样品开始逐个收起，“全部收起”一键完成。
- **结果报告 Excel**：导出为一张扁平单表（表头：来样序号、样品名称、各结果项目），不带业务工作簿的说明页和格式标识；文件名形如 `结果报告-全局默认-20260901.xlsx`，自动带上顺序模板名和日期。可选择设置页维护的结果元素顺序模板决定列顺序。

### 5.10 XRF 元素/氧化物报告口径

XRF 可报元素（`Fe`）或氧化物（`Fe2O3`），系统按“元素族”统一口径，同一份报告每种元素只出一个结果：

- **填写口径**：来样页“报告默认项目”直接填 `CaO, SiO2, Fe` 等，也可用“元素口径 / 氧化物口径”快捷按钮一键预填；同一元素族先填写的口径优先。模板保存同样有效，新样品自动继承。
- **换算规则**：仪器直出目标口径时直接采用；缺失时按 `common_oxides` 化学计量系数自动换算（如只有 `Fe` 时自动换出 `Fe2O3`，系数约 1.4297），换算行会标注来源（如“由 Fe × 1.4297”）。多价态（FeO/Fe2O3/Fe3O4）不自动猜测，需明确选择。
- **结果页调整**：XRF 组成网格右上角“口径”按钮可为当前样品按元素族单独改口径、勾选是否参与；直出值与换算值同族并存且偏差超过 1% 时显示核对警告，缺口径的项目不写入报告（不用 0 代替）。
- **数据基础**：UniQuant 上传时同时保存元素名与氧化物名（`xrf_values.alt_name`），仪器原值永不覆盖。详见 `docs/xrf-element-oxide-reporting.md`。

## 6. 报告与计算

### 6.1 两种规范打印票据

报告页支持勾选多个已审核样品批量编排：所有选中样品同时展开，可上下调整整组顺序；打印时多个样品的原始分析记录合并到同一张 A4 横向表（共用表头、备注和签名区），A5 报告票也按编排顺序合并输出。票面信息可批量保存到全部已选样品。

已审核样品卡片强制每行 4 张、分页显示（每页 20/50/100 可选）；跨页勾选的样品始终显示在列表顶部并保留顺序号。分析人员默认取全部所选样品审计记录中填写或修改过结果数据的用户，按修改次数降序排列（如 `CXL GZQ`）；票面字段输入时预览实时同步，点“保存整组票面信息”才写入数据库。

- **原始分析记录（A4 横向）**：公司抬头、分析日期、来样编号、样品名称、分析项目、样品净重、首次定容、检测体积（如 `5/100`）、每遍原始读数、换算结果、分析者、备注和审核。
- **分析报告票（A5 纵向）**：公司抬头、报告编号、来样单位、分析时间，以及“编号—样品名称—元素—最终结果”，底部带分析/审核签字区和报告声明。

票面信息在报告页填写并保存到样品。系统计算明细仍可在两张票据下方展开查看；同一任务只计算勾选“参与”的读数，多遍自动平均，单遍直接采用。

分析人和审核人会随工作流操作自动记录。报告页允许具备权限的用户手工覆盖最终报告行，覆盖操作必须再次验证用户密码，并完整记录覆盖前后内容和操作者；原始读数及系统计算结果不会被覆盖删除。

报告元素顺序分三级：设置页维护全局默认顺序；样品模板可以保存自己的元素顺序；报告页还可用上下箭头为当前样品单独调整，或点击“恢复默认元素顺序”重新跟随全局设置。模板或样品未列出的新增元素会按全局默认顺序接在后面。同一元素有多个仪器结果时，明细行按设置中的默认仪器顺序排列。

其他样不生成常规元素分析票，报告页按对应专项方法生成 A4 横向原始记录，包含检测日期、样品名称、编号、分组原始数据、自动计算结果、备注和签字栏，版式参照 `image/` 中的水分、煤/炭精、石膏、碳硫和量热仪记录表。

> 石膏二水硫酸钙和氯离子的计算系数目前按常见化学计量关系配置，正式使用前应按实验室现行 SOP 核对。

### 6.2 换算公式

#### 固体样品（ICP / AAS / TOC / F 电极类）

原始值 `C` 为 ppm（mg/L），首次定容体积 `V`（mL），二次稀释倍数 `D`，称样量 `m`（g）。若票面写作 `a/b`，则 `D = b ÷ a`：

```text
w(%) = C × V × D / (m × 10^4)
```

例如：C = 8 ppm，V = 250 mL，二次稀释为 `5/250`，即 D = 50，m = 2 g：

```text
8 × 250 × 50 / (2 × 10000) = 5.0%
```

#### 液体样品（ICP / AAS / TOC / F 电极类）

```text
结果 (mg/L) = C × D
```

ICP-MS 例外：原始值按 ppb（μg/L）录入。固体样换算为质量分数时使用：

```text
w(%) = C × V × D / (m × 10^7)
```

液体样结果保持为 ppb，并按二次稀释倍数计算 `C × D`。

#### XRF

原始值直接作为质量分数 %：

```text
结果 (%) = raw
```

#### pH 计

```text
结果 = 原始 pH 值，单位 pH
```

#### 滴定

由滴定方法公式计算。原子量等固定值保存在方法的“固定常数”中，称样量优先从溶样方案读取；数据页只为剩余的必填实验数据生成输入框。

| 变量 | 含义 |
|------|------|
| `V`  | 滴定剂消耗体积（mL） |
| `V0` | 空白体积（mL） |
| `c`  | 滴定剂浓度（mol/L） |
| `M`  | 被测元素原子量（g/mol），通常由方法预存 |
| `m`  | 称样量（g），优先从溶样方案读取 |

公式示例（Zn-EDTA 络合滴定，方法预存 `M=65.38`）：

```text
(V - V0) * c * M / m / 1000 * 100
```

结果以质量分数 % 计。

系统预置 Zn-EDTA、Fe-EDTA 和 Fe-重铬酸钾三种方法。预置原子量保留两位小数；具体前处理、终点判断和方法适用范围仍应以实验室采用的标准/SOP为准。

## 7. 设置页

### 7.1 分析项目（元素 / 指标）

- 添加新的元素或指标，添加后立即可在来样页 NLP 识别。
- 删除分析项目会级联删除其关联关系，谨慎操作。

### 7.2 定容容量与二次稀释方式

定容容量与二次稀释放在同一个设置面板。新建溶样和样品模板默认选择不可移除的 `250 mL`；可新增或停用其他容量。停用容量只影响新建时的下拉选项，历史样品仍显示并保留原容量。

填写“移取多少 mL”和“再次定容到多少 mL”，系统自动生成票面写法和换算倍数。例如：

```text
移取 5 mL → 定容至 100 mL → 票面显示 5/100 → 计算倍数 20
```

系统预置 `5/100`、`5/250`、`10/100`、`10/250`。设置页删除采用安全停用：它会立即从新样品和模板的可选列表中消失，但历史样品仍保留原写法和换算倍数；重新添加同一写法即可恢复。旧数据库里的“20倍”“50倍”等选项仍可继续使用。

### 7.3 仪器与可测项目

- 新增仪器时选择其数据类型（xrf / ppm / ppb / percent / function / ph），类型决定数据录入页的单位和换算方式；ICP-OES、AAS 等技术名称直接保留在仪器名称中。
- 点击“可测项目”可勾选该仪器能测哪些元素，没勾选的不会出现在仪器下拉里。

### 7.4 滴定方法

- **名称**：如“EDTA 络合滴定钙镁”。
- **公式**：只能用 `V`、`V0`、`c`、`M`、`m` 和数字、运算符。公式按 % 计算。
- **固定常数**：使用 `名称=数值`，多个常数用空格或逗号分隔，如 `M=65.38`。已固定的变量不会再要求操作者输入。
- **备注**：可选说明。

### 7.5 样品模板

保存模板时指定：

- 名称
- 样品类型
- 是否打荧光
- XRF 方法和默认参与报告的 XRF 项目；纯 XRF 模板可以不配置常规溶样项目
- 包含的分析项目，以及每个项目的默认仪器和滴定方法
- 任意多路溶样的称样量、首次定容体积、二次稀释方式、份数和分路项目

设置页可以新建、编辑和删除完整模板。样品卡展开后也可点击“保存当前方案”，直接把该样品的项目、溶样和已有仪器选择保存为新模板。应用模板后，新建的分析任务会直接带入默认仪器；复制已有样品新建时也会继承仪器设置。

## 8. Excel 业务工作簿

系统提供四种 `.xlsx` 业务工作簿，均带格式标识 `toy-lims-business-workbook`（当前版本 1），每个工作簿第一页是“说明”页，记录格式、版本、业务类型、样品身份、更新标记和生成时间：

| 工作簿 | 入口 | 文件名 | 可回传 |
|--------|------|--------|--------|
| 样品总览 | 来样页“导出总览” | `样品总览-起始日期-截止日期.xlsx` | 否（只读查阅） |
| 样品方案 | 来样页编辑器“导出样品方案” | `样品方案-编号.xlsx` | 可：从 Excel 新建 / Excel 覆盖方案 |
| 样品数据 | 数据页“导出数据 Excel” | `样品数据-编号.xlsx` | 可：Excel 覆盖数据 |
| 分析报告 | 报告页“导出 Excel 报告” | `分析报告-编号.xlsx` | 否（只读导出） |

> Excel 是单样品的编辑与传递工具，**不是全量备份**。任何 Excel 都不包含用户、密码、权限、审计日志和基础设置（分析项目、仪器、稀释方式、定容容量、滴定方法、模板等）。正式库的完整备份与恢复应使用 PostgreSQL `pg_dump` 或数据库服务器快照。

此外，结果页还提供独立的**结果报告**导出（`结果报告-顺序名-日期.xlsx`）。它是一张扁平单表，不带“说明”页和业务格式标识，也不支持回传，用于快速对外传递检测结果，详见 5.9 节。

### 8.1 通用规则

- 导出只需终端登录；回传上传按内容要求能力：新建/覆盖方案需要“样品登记与修改”，覆盖数据需要“检测数据录入”；普通终端还需先通过用户密码授权。
- 上传仅接受 `.xlsx` 且不超过 20 MB，前端会先弹出确认对话框。
- 服务端在开写事务**之前**完成全部解析与业务校验：格式标识、版本、业务类型、工作表、表头不符，或数据区含公式，都会直接拒绝，数据库零改动。校验通过后的写入包在事务与保存点中执行，任何错误整体回滚。
- 三类导入均写入审计（`从 Excel 新建样品`、`从 Excel 覆盖样品方案`、`从 Excel 覆盖检测数据`），保留修改前后快照。

### 8.2 样品总览导出（只读）

按创建日期的闭区间导出样品列表，跟随来样页当前的类型筛选（固体/液体/其他/全部）、搜索词和“显示已作废”勾选。工作簿含“说明”和“样品总览”两页，每行列出编号、名称、类别、流程、状态、创建/更新时间、溶样数、任务数、完成任务数、读数数、XRF 结果数、分析项目、客户、报告编号、分析日期、分析员、审核员等 21 列，便于业务查阅与核对。

### 8.3 样品方案工作簿（新建与覆盖）

工作簿含“说明”“样品信息”“溶样方案”“检测方案”四页。专项样品的溶样页标注“无需溶样”，检测页只有一行专项方法。

- **从 Excel 新建**：忽略工作簿中的样品 ID、编号和更新标记，由系统生成新的正式编号，初始状态为“未制样”。勾选 XRF 时工作簿中的 XRF 方法必须存在且类型正确。
- **Excel 覆盖方案**：工作簿的样品 ID、LIMS 编号、更新标记必须与当前样品一致，否则拒绝（更新标记过期即“样品已被他人更新，请重新导出后再上传”）。已审核、已出报告、已作废的样品禁止覆盖；常规样与其他样不能互转；已有专项数据的样品不能更换专项方法。
- 合并语义：溶样按 ID 原地更新或新建，文件中删除的溶样会一并删除；任务 ID 命中且溶样、项目未变时保留既有读数，仪器或方法变更会清空该任务读数并回到待测；任务消失则删除。**XRF 仪器任务完全只读**，不能通过 Excel 新增、删除或修改。

### 8.4 样品数据工作簿（覆盖检测数据）

工作簿含“说明”“样品”（只读标识）“数据录入”“专项数据”“XRF结果”（只读）五页。“数据录入”只含非 XRF 常规任务的平行读数：原始读数、参与平均、终值、公式变量（JSON），以及任务级的辅助校正（JSON）和报告选择。

- 仅当样品处于“测量中”至“已测量 / 未出报告”阶段时允许覆盖；前端在其它状态禁用按钮，服务端同样强制校验。
- 常规样按任务原子替换：只处理工作簿中出现的任务，未列出的任务不受影响；任务内读数先整体删除再按工作簿行重建；整行空白表示清空该任务数据；辅助校正和报告选择在同一任务内必须一致。
- 其他样按字段合并：只允许录入 schema 中的非公式字段和备注；出现的字段覆盖原值、留空表示清空、未列出的字段保留；写回后由系统公式重新计算，计算结果列只读。
- XRF 结果永远不会被 Excel 修改。
- 样品 ID、编号、更新标记三重核对不符时返回 409，需重新导出后再传。

### 8.5 分析报告导出（只读）

与报告页数据源完全同源，含手工覆盖后的最终结果、“分析报告”“原始分析记录”“计算明细”三页；样品未审核发布时标注“（草稿）”。没有对应的上传入口。

### 8.6 在 Excel 中编辑的规则

- 不要修改工作表名称、第 3 行的中文表头和“说明”页的格式标识；数据从第 4 行开始。
- ID 与名称同时出现，二者冲突会被直接拒绝，不要手工改 ID。
- 空白单元格表示空值；布尔字段接受 `0/1` 或 `true/是`。
- `公式变量(JSON)`、`辅助校正(JSON)`、`报告项目顺序(JSON)` 等字段必须保持合法 JSON。
- 数据区域不接受 Excel 公式，发现即拒绝整个文件；导出时已对以 `= + - @` 开头的文本加防注入前缀。
- 编辑前建议重新导出，避免更新标记过期导致上传被拒绝。

## 10. 版本与迁移说明

`toy-lims` 仍在持续迭代，数据库结构会随业务变化。正式运行现已切换到 PostgreSQL：

- `server/db_schema.py` 集中保存表结构、旧 SQLite 升级、种子数据和初始化过程；`app.init_db()` 仅保留兼容包装。
- `server/db_backend.py` 隔离连接、参数占位符、时间函数、自增 ID 和两种数据库的行对象差异。
- 初始化过程在 PostgreSQL 中幂等创建当前 schema 和索引；SQLite 旧库迁移逻辑仍保留，供测试和旧档案使用。
- `server/migrate_to_postgres.py` 迁移全部配置、用户和终端，同时按要求只保留指定样品及其关联数据；默认样品名为 `RY28888`。
- 迁移工具先执行 SQLite 完整性检查并创建迁移前 `.db` 备份，再写入 PostgreSQL、校准 identity 序列并核对关键行数。

迁移预演使用 `python server/migrate_to_postgres.py --dry-run`；明确替换目标库时使用 `python server/migrate_to_postgres.py --replace`。迁移完成后应保留原 `lims.db` 和迁移前备份，不要把旧库与 PostgreSQL 同时投入写入。

## 11. 开发与验证

```powershell
cd server
python -m unittest discover -s tests -p "test_*.py"
```


客户端发布命令和配置说明见 `client/standard/README.md` 与 `client/xrf/README.md`。发布目录是构建产物，不应把数据库、服务端密钥或用户密码复制进去。

## 12. 使用建议

- 一个真实样品可以拆成多路溶样，每路独立设置稀释倍数和测定项目，避免“一刀切”。
- 平行样用“份数”生成，名称规则统一为 `样品名-序号*倍数`，便于追溯。
- XRF 是“粗扫”，推荐勾选；精密定量结果走溶解稀释后的 ICP / AAS / 滴定。
- 液体样不需要称样/定容，系统会自动隐藏这些字段并按液体公式计算。

## 13. 局限与后续可扩展方向

当前实现尚未包含：

- 符合监管要求的电子签名（当前已有能力控制、审核流和审计，但不是合规电子签名）
- 样品二维码 / 条码
- 除现有 OXSAS/XRF 集成外的通用仪器原始文件自动解析
- 复杂质控图（平行样偏差、加标回收等）
- 报告单 PDF 导出

这些都可基于现有模型继续扩展。
