# XRF 单质与氧化物报告口径方案

## 1. 问题

OXSAS 普通定量和 UniQuant 可能返回两种组成口径：

- 元素口径，例如 `Fe`、`Si`、`Ca`。
- 氧化物口径，例如 `Fe2O3`、`SiO2`、`CaO`。

已确认 UniQuant 的结构与普通定量不同：同一条 `JobChan` 经 `Line.LinkAtom → Atom` 后，`Atom.Name` 是元素名，`Atom.OxideName` 是对应氧化物名。因此，只要该通道定义了氧化物形式，就一定同时具有元素形式的名称；但只有元素名的通道不一定有氧化物名。`JobChan` 当前只有一列最终浓度 `Conc`，其数值口径由 `GeneralData.Chemistry` 决定，并不是数据库同时保存两套独立浓度。

现有客户端查询已经同时读取 `Atom.Name` 和 `Atom.OxideName`，但随后根据 `Chemistry` 只选择一个名称上传。后续实施报告口径时，应把这对名称和当前浓度口径一起保留，不能只上传显示名称。

同一个客户、样品类型或报告模板可能要求不同口径。当前 `xrf_values.name` 原样保存仪器项目名，这是正确的原始记录，但仅靠逐项“参与”无法表达“本报告的铁统一报 Fe，另一份报告统一报 Fe2O3”。如果直接把元素和氧化物都参与汇总，还可能把不同口径错误平均或同时打印。

## 2. 核心原则

1. **仪器原值永不覆盖**：`xrf_values` 继续保存仪器返回的项目名、数值和分析来源，不把 Fe 原值改写为 Fe2O3。
2. **报告口径独立配置**：报告选择的是目标项目，如 `Fe` 或 `Fe2O3`，而不是修改仪器数据。
3. **直取优先**：当前浓度口径已经等于报告目标时直接使用，不重复换算。
4. **口径不同时才换算**：普通定量缺少目标项目，或 UniQuant 当前 `Chemistry` 口径与目标名称不一致时，才允许按化学计量换算。
5. **不同价态不猜测**：FeO、Fe2O3、Fe3O4，MnO、MnO2、Mn3O4 等必须由模板或用户明确选择，系统不能仅凭元素名推断价态。
6. **同一元素族只出一个口径**：一份报告中 Fe 与 Fe2O3 默认互斥，除非报告模板明确要求两者都列出。
7. **换算过程可追溯**：报告结果需标记“仪器直出”或“由 Fe 换算为 Fe2O3”，并保留来源 XRF 值 ID 和换算系数。
8. **全精度计算、5 位有效数字显示**：换算使用数据库原值和完整系数，只在最终显示或导出时统一为 5 位有效数字，禁止连续来回换算。

## 3. 参考数据

数据库参考数据分两层：

- `chemical_elements`：1–83 号元素的原子序数、符号、中文名和原子量。
- `common_oxides`：常见报告氧化物，保存化学式、中文名、对应元素、元素和氧的化学计量数、摩尔质量、元素转氧化物系数及是否为惯用口径。

常见氧化物表不是报告配置，也不代表系统自动认定价态。它只提供经过统一原子量计算的候选项和换算依据。

## 4. 换算公式

设氧化物为 `E_aO_b`：

```text
氧化物摩尔质量 = a × Ar(E) + b × Ar(O)
元素质量分数   = a × Ar(E) ÷ 氧化物摩尔质量
元素转氧化物系数 = 氧化物摩尔质量 ÷ (a × Ar(E))
氧化物结果 = 元素结果 × 元素转氧化物系数
元素结果   = 氧化物结果 ÷ 元素转氧化物系数
```

例如 Fe 转 Fe2O3：

```text
Fe2O3 = Fe × (2 × Ar(Fe) + 3 × Ar(O)) ÷ (2 × Ar(Fe))
```

所有系数由 `chemical_elements` 的原子量和 `common_oxides` 的化学计量数生成，不在业务代码中写死。

## 5. 建议的报告配置模型

当前样品使用 `xrf_report_items` 保存默认参与项目。后续实施时建议改为结构化配置，例如：

```json
[
  {"family": "Fe", "target": "Fe2O3", "include": true, "allow_conversion": true},
  {"family": "Si", "target": "SiO2", "include": true, "allow_conversion": true},
  {"family": "Cl", "target": "Cl", "include": true, "allow_conversion": false}
]
```

配置可依次继承：

1. 报告版式或结果顺序模板的默认口径。
2. 样品模板的默认口径。
3. 当前样品的覆盖设置。

最终选择应持久化到样品，而不是仅保存在浏览器中。建议新增结构化字段或独立表，不继续扩展逗号分隔字符串。

## 6. 结果选择算法

对每个目标项目按以下顺序处理：

1. 找到当前样品唯一关联的 XRF 分析。
2. UniQuant 先根据 `GeneralData.Chemistry` 确定 `JobChan.Conc` 当前属于元素还是氧化物口径；目标等于当前口径名称时直接采用，目标等于同一 `Atom` 的另一名称时换算。
3. 普通定量结果中存在与目标化学式完全相同的独立项目时，直接采用该值。
4. 普通定量不存在目标项目且允许换算时：
   - 目标是氧化物，且存在同族元素值时，从元素值换算。
   - 目标是元素，且配置明确指定来源氧化物时，从氧化物值换算。
5. 普通定量中元素和目标氧化物作为独立项目同时存在时不平均，优先使用目标项目直出值；UniQuant 同一通道的名称对不属于两条独立项目。
6. 如果同族存在多个非目标氧化物，不自动挑选，提示用户明确来源。
7. 如果没有可靠来源，结果保持缺失并提示“缺少目标口径”，不能用 0 代替。

## 7. 一致性校验

普通定量结果或两次不同口径的 UniQuant 任务同时给出元素值和对应氧化物值时，可以进行只读核对：

```text
相对偏差 = |氧化物直出值 - 元素换算值| ÷ max(|氧化物直出值|, 报告限)
```

偏差阈值应由 XRF 方法配置，不建议全局写死。超限只显示警告，不自动覆盖任一结果。同一个 UniQuant `JobChan.Conc` 的元素名和氧化物名只是同一数值的两种候选表示，不能当作两条独立实测值做一致性比较。UniQuant 的元素模式、氧化物模式以及归一化到 100% 的设置必须保留在分析元数据中，校验时应区分是否经过归一化。

## 8. 页面建议

### 结果页

- 仍显示紧凑的 XRF 最终组成网格。
- 按元素族组织候选结果，例如 Fe 族可选择 `Fe`、`FeO`、`Fe2O3`、`Fe3O4`。
- 每个元素族只勾选一个报告目标；有多个价态时使用下拉选择，不用多个互相独立的勾选框。
- 结果旁显示来源：`直出` 或 `由 Fe × 1.4297 换算`。
- 仪器原始组成可展开查看，但不与报告目标混在一起。

### 样品模板与报告版式

- 提供“元素口径”“常用氧化物口径”“自定义”三种快捷方式。
- “常用氧化物口径”只是预填候选，Fe、Mn、Co、Cu、Pb 等多价元素仍需模板明确指定。
- 模板保存后，新样品继承；修改模板不追溯改变已有样品。

## 9. 审计与导出

审计至少记录：

- 元素族与目标项目。
- 直出或换算。
- 来源 XRF 值 ID、原值和单位。
- 使用的氧化物、换算系数和最终值。
- 操作者、时间以及样品模板/报告版式来源。

Excel、A4 原始记录和 A5 报告票应使用同一份已解析报告结果，禁止各导出模块自行重复换算。

## 10. 分阶段实施

### 阶段一：参考数据（本次）

- 建立 `chemical_elements` 和 `common_oxides`。
- 暂不改变当前 XRF 参与勾选、报告计算和打印行为。

### 阶段二：结构化口径配置

- 新增样品级 XRF 报告目标配置。
- 将现有 `xrf_report_items` 迁移为明确的元素或氧化物目标。
- 结果页按元素族单选报告口径。
- 扩展 UniQuant 上传载荷，同时保存 `Atom.Name`、`Atom.OxideName` 和 `GeneralData.Chemistry`，避免客户端提前丢弃另一种名称。

### 阶段三：换算与一致性检查

- 实现直取优先、缺项换算和来源追溯。
- 增加元素/氧化物直出值一致性警告。
- 报告和 Excel 统一读取已解析结果。

### 阶段四：模板化

- 样品模板、XRF 方法和报告版式保存默认口径。
- 根据不同客户或产品类型快速切换元素/氧化物报告方案。
